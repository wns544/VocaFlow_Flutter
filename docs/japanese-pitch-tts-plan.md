# 일본어 액센트 음성·높낮이 표시 상세 구현 계획

작성일: 2026-10-05

상태: 1차 핵심 구현 및 30개 표본 팩 생성 완료. 실제 두 기기 청취·가져오기 검증과 후보 선택 화면은 아직 완료로 판정하지 않는다.
기초 조사: `japanese-pitch-tts-feasibility.md`.

## 1. 목표와 범위

단어의 표기·읽기에 맞는 사전 액센트를 찾아, 동일한 액센트 정보를 음성 생성과 카드 높낮이 표시에 사용한다. 뜻이 다른 동음이의어를 읽기만으로 합치지 않는다. 합성음이 사전 액센트를 실제로 재현하는지는 별도로 검증한다.

사용자가 선택한 방향:

- PC에서 미리 음성을 생성하고 휴대폰에 가져온다. 상시 서버나 유료 생성 API는 사용하지 않는다.
- 뜻이 애매한 항목은 사전 후보를 보고 직접 선택한다. AI 의미 판정은 1차 버전에서 제외한다.
- 높낮이 표시는 정답 공개 후 읽기와 함께 나타난다. 설정으로 끌 수 있다.

이번 계획에서 정한 기본값:

- Android 우선. 웹은 기존 TTS를 유지하며 음성팩 메뉴를 노출하지 않는다.
- 기본 음성 후보는 VOICEVOX Nemo 여성1. 이름으로 찾은 실제 speaker UUID/style ID와 엔진·모델 버전을 기록한다. 임의 숫자 ID를 고정하지 않는다.
- 여성1의 샘플이 검증을 통과해야 대량 생성한다. 통과하지 못하면 자동으로 다른 목소리로 바꾸지 않고 표본 결과와 대안을 보고한다.
- 음성팩과 사용자 발음 선택은 로컬 파일로 보관한다. 두 폰의 자동 동기화는 1차 범위 밖이다. 동일 팩 및 선택 내보내기 파일을 가져와 맞춘다.
- 음성팩 우선 재생 및 정답 뒤 높낮이 표시 기본 켬. 기존 자동 읽기 설정은 그대로 따른다.
- 일본어 단어 기본형의 단독 발음부터 지원한다. 문장 억양, 활용형 자동 생성, 방언 선택, 모든 단어의 정확성 보장은 제외한다.

## 2. 절대 변경하지 않는 것

- Firestore `users/{uid}/vocabBooks/*/words`에 쓰기·삭제·새 필드 추가를 하지 않는다.
- 기존 단어, 뜻, 읽기, 예문, 학습 기록을 이 기능 때문에 바꾸지 않는다.
- 액센트 정보는 Word 모델·카드 백업 payload에 섞지 않고 별도 저장한다.
- 회독, 알음/모름, 이어서하기, 되돌리기, 즐겨찾기, 한자 사전 및 내부 브라우저 동작을 유지한다.
- 코랄 아이콘과 기존 서명 방식을 유지한다. 버전 변경, 커밋, 릴리즈는 구현·검증 이후 별도 배포 요청에 따른다.
- 배포 전에는 전체 회귀 테스트와 Android 빌드를 통과시키며, 버전 변경·커밋·릴리즈는 별도 배포 요청에 따른다.

## 3. 사용자 흐름

1. 설정 → 일본어 발음 → ‘음성 생성용 단어 내보내기’에서 단어장을 선택한다.
2. 단어 표기·읽기·뜻 및 연결용 식별자만 파일로 내보낸다. 예문·학습 기록·계정 토큰은 포함하지 않는다.
3. PC 생성 도구에 해당 파일을 지정하면 사전 조회 → 후보 음성 생성 → 검증 보고서 → 음성팩을 만든다.
4. 휴대폰 설정 → ‘음성팩 가져오기’에서 파일을 선택한다. 새 음성 수, 연결 가능 카드 수, 미해결·실패 수, 설치 크기를 먼저 보여준다.
5. 카드 정답 공개 시 확정 가능한 액센트의 높낮이가 표시된다. 기존 듣기 버튼과 자동 읽기는 같은 재생 경로를 쓴다.
6. 후보가 여러 개이면 ‘발음 선택 필요’를 표시한다. 사용자가 ‘발음 설정’에서 후보를 비교하고 이 카드에 적용한다.
7. 두 번째 폰에도 같은 팩을 가져온다. 첫 번째 폰의 ‘발음 선택 내보내기’를 추가로 가져오면 개인 선택까지 맞춰진다.

USB는 필수가 아니다. 파일 전달 수단은 사용자가 선택하며 앱이 임의로 업로드하지 않는다. 개인 단어·뜻이 들어간 팩/요청 파일은 공개 GitHub 릴리즈에 올리지 않는다. APK와 개인 음성팩은 별개다.

## 4. 사전 매칭 및 판정 규칙

우선순위는 ‘이 카드의 유효한 사용자 선택 → 표기+읽기 정확 일치의 유일 후보 → 미확정’이다.

- Unicode 정규화 및 읽기의 히라가나/가타카나 동등 비교를 사용하되 원문을 보존한다. 장음, 촉음, 작은 가나, 구두점 제거 등 의미를 바꾸는 과도한 정규화는 금지한다.
- 읽기가 비어 있으면 표기로 후보만 찾는다. 읽기 추정값을 기존 카드에 기록하지 않는다. 사용자가 고르기 전에는 확정하지 않는다.
- 가나만 있는 표기는 동음이의어 위험이 있으므로 사전의 가나 항목이 직접 일치하는 경우와 다른 한자 표기의 읽기 검색 결과를 구분한다. 후자는 후보 제시만 하고 자동 적용하지 않는다.
- 같은 표기·읽기의 여러 액센트는 허용 변이일 수도 있다. ‘첫 번째가 정답’ 또는 ‘뜻이 각각 다름’이라고 가정하지 않는다.
- 한국어 뜻은 사용자의 후보 판단과 카드 변경 감지에 사용한다. Kanjium에는 한국어 의미 식별자가 없으므로 자동 의미 매칭을 주장하지 않는다.
- 복수 읽기가 섞인 필드, 지원하지 않는 문자, 구/문장은 임의 분해하지 않고 ‘직접 확인 필요’로 보낸다.
- 후보를 선택해도 표시는 ‘사용자 선택’이며 ‘전문가 검증’으로 승격하지 않는다.

상태는 두 축으로 나눈다:

| 액센트 상태 | 의미 |
| --- | --- |
| 사전 일치 | 표기·읽기에 해당하는 단일 사전 후보 |
| 사용자 선택 | 사용자가 해당 카드에 후보를 선택함 |
| 선택 필요 | 후보가 여럿이거나 읽기 확인이 필요함 |
| 정보 없음 | 지원 가능한 사전 항목이 없음 |
| 재확인 필요 | 카드 내용 변경 또는 선택한 후보의 출처 변경 |

음성 상태는 별도로 ‘팩 음성 있음 / 기본 TTS / 재생 실패’로 관리한다. 사전 일치가 합성음의 청취 검증을 의미하지 않는다. 검증된 표본만 별도 QA 기록을 갖는다.

## 5. 높낮이 표시

- 한국어 UI 명칭은 ‘일본어 높낮이’. 상세 설명에서 ‘고저 액센트’라고 안내한다. 높낮이 선은 실제 음성 파형이 아니라 사전 액센트의 도식이다.
- 정답 앞면에서는 높낮이·액센트 번호·후보 안내를 모두 숨긴다. 기존 읽기 앞면 표시 옵션이 있더라도 높낮이는 정답 뒤에만 보인다.
- 학습 화면의 큰 ‘발음 자동 재생’ 토글 영역은 두지 않는다. 상단 툴바에서 36px 원형 스피커 버튼 하나로 켜고 끈다. 켜짐은 코랄색 스피커, 꺼짐은 회색 빗금 스피커이며 변경 순간에만 짧은 상태 안내를 표시한다.
- 정답 공개 후 읽기 영역에 낮음/높음 선을 한 줄로 표시하고 하강 지점에 코랄색 표시를 넣는다. 색만으로 구별하지 않는다.
- 음절이 아닌 박(모라) 단위로 배치한다. きゃ는 한 박, っ·ん·ー는 각각 한 박이다. 외래어의 작은 가나 결합은 명시적인 조합표와 테스트로 처리한다. 해석 불가능하면 선을 만들지 않는다.
- N박에서 액센트 값은 0..N만 허용한다. 0은 하강 없음, 1은 첫 박 뒤 하강, k>1은 첫 박 낮음 → k까지 높음 → 이후 낮음으로 도식화한다. 1박 단어도 별도로 테스트한다.
- 0과 N은 단독 발음만으로 구별하기 어려울 수 있다. 상세 화면에만 회색 ‘뒤 조사’ 예시를 추가하여 연결 시 차이를 설명한다. 모든 품사에 실제 조사 음성을 임의로 붙이지 않는다.
- 기본 카드에는 숫자·전문 용어를 과하게 넣지 않는다. 상세 화면에서 0형/하강 위치, 출처, 상태를 확인한다.
- 미확정 항목은 단정적인 선 대신 짧은 상태 안내를 보인다. 사전 액센트는 있으나 음성이 없으면 선을 표시할 수 있으나 ‘기본 TTS: 표시된 높낮이와 다를 수 있음’을 상세 및 재생 상태에 표시한다.
- 음성팩을 사용하지 않는 설정에서는 동일한 경고 원칙을 적용한다.
- 큰 글자·작은 화면에서 영역을 잘라내지 않도록 정답 읽기 영역을 가변 높이로 바꾼다. 긴 단어는 박 단위로 줄바꿈하고 선의 연결을 표시한다. 스크린리더에는 ‘둘째 박 뒤 낮아짐’ 등으로 제공한다.

## 6. 발음 선택·수정 화면

- 기존 듣기 버튼의 짧은 탭은 재생을 유지한다. 정답 공개 후 ‘발음 설정’ 진입점을 제공한다. 길게 누르기만으로 숨기지 않는다.
- 화면 구성: 현재 단어·읽기·뜻 → 현재 상태 → 후보별 사전 표기/읽기/높낮이 선/출처/미리듣기 → ‘이 카드에 적용’ → ‘선택 초기화’.
- 모든 후보는 한 번에 하나만 재생한다. 미리듣기만으로 저장되지 않는다.
- 후보 음성은 PC 단계에서 미리 생성한다. 파일이 없는 후보의 미리듣기를 기본 TTS로 대체하여 정확한 후보 음성인 척하지 않는다. ‘음성팩 추가 필요’를 표시한다.
- 음성이 없는 후보도 사전 정보로 선택할 수 있으나 ‘높낮이 표시만 적용, 재생은 기본 TTS’ 확인을 보여준다.
- 1차 버전은 사전 후보 선택만 지원한다. 임의 하강점 편집과 즉석 음성 생성은 제외한다.
- 적용 범위는 현재 카드만. 다른 카드나 같은 읽기의 다른 단어를 자동 변경하지 않는다.
- 초기화는 별도 선택값만 지우고 사전 판정으로 돌아간다. 카드 원문·학습 기록은 건드리지 않는다.

## 7. 저장 구조·두 폰 간 이전

앱 전용 로컬 저장소 `pronunciation/v1/`을 사용한다. 계정 UID의 로컬 해시별 영역과 비로그인 영역을 분리하고 로그아웃 시 현재 재생·선택 메모리를 해제한다. 비로그인 선택을 계정으로 자동 병합하지 않는다.

- `CardPronunciationRef`: bookId + wordId + fingerprint. fingerprint는 정규 직렬화한 표기·읽기·뜻의 SHA-256이며 Dart의 실행환경 의존 hashCode를 쓰지 않는다.
- `AccentCandidate`: candidateId, 원문 표기/읽기, 모라 배열, 하강 위치, 사전 버전/원본 행 식별자, 출처.
- `PronunciationSelection`: 카드 참조, candidateId, 갱신 시각, revision, 초기화 tombstone. 발음 정정이 원문 수정으로 전파될 경로를 만들지 않는다.
- `AudioAsset`: content hash, candidateId, voice UUID/style ID, engine/model 버전, 생성 설정, 실제 생성 query hash, 크기·재생 시간·샘플 형식.
- `PackManifest`: schemaVersion, packId, generatorVersion, 사전 snapshot hash, 후보/음성 인덱스, 연결 참조, 파일별 SHA-256, 출처·라이선스.

의미가 다른 카드는 선택 상태를 공유하지 않는다. 확정된 읽기·액센트·음성 생성 설정이 완전히 같을 때에만 음성 파일을 중복 제거할 수 있다.

카드 fingerprint가 바뀌면 기존 선택은 보존하되 활성 적용을 중단하고 ‘재확인 필요’로 표시한다. ID가 다른 가져오기/복제 카드에 선택을 추정 적용하지 않는다. 연결 실패 목록을 제공한다.

두 폰의 선택 파일 가져오기 규칙:

- 정확한 카드 참조·fingerprint가 일치하는 것만 대상이다. 다른 계정에서 내보낸 선택은 자동 적용하지 않는다.
- 같은 선택은 중복 무시, 충돌은 현재 값 유지가 기본이며 사용자가 항목별로 가져올 값을 고른다. 시계 차이 때문에 갱신 시각만으로 덮어쓰지 않는다.
- 초기화도 명시적으로 내보내며 옛 파일이 무조건 선택을 되살리지 않도록 충돌로 처리한다.
- 동기화 완료라는 표현 대신 ‘선택 N개 가져옴’을 쓴다. 자동 동기화·Firebase Storage 업로드·새 Firestore 컬렉션은 이번 버전에 추가하지 않는다.

## 8. PC 생성 도구

- 도구는 저장소 `tools/pronunciation/`에 두고 Windows 실행 안내/런처를 제공한다. 엔진·모델은 저장소 밖 `D:\DevTools\VocaFlowSpeech\`에 둔다. 실제 설치는 구현 단계에서만 한다.
- 엔진은 localhost에만 바인딩한다. 외부 서비스로 단어/뜻을 전송하지 않는다. 사전·엔진 배포물을 받는 네트워크 사용과 단어 처리의 로컬 실행을 구분한다.
- 입력 요청 파일 읽기 → 버전 고정 사전 조회 → 유효 후보 목록 → 생성 크기 예상/실패 목록 → 음성 생성 → 패키징 순서다.
- 단일 후보만이 아니라 다중 후보 음성도 모두 생성하여 폰에서 비교할 수 있게 한다. 비정상적으로 후보가 많은 입력은 자동 잘라내지 않고 별도 검토 목록으로 제외한다.
- 대량 생성은 최초 30개 표본 품질 관문 통과 뒤 수행한다. 기본 생성 동시성 1, 파일별 재시도 최대 2회, 진행률/중단/재개를 지원한다.
- API의 요청별 accent phrase/query 편집을 사용한다. 재생마다 공유 사용자 사전을 수정하지 않는다. 대상 Nemo 엔진에서 액센트 0, 1, 중간, 끝 위치의 실제 동작을 표본 단계에서 확인한다.
- 엔진의 읽기·모라·액센트가 의도와 다르면 성공으로 저장하지 않는다. 피치 재계산이 필요한 경우 해당 엔진 공식 API의 지원 경로를 사용하고 최종 합성 query를 보관한다.
- 기본 출력은 24kHz mono PCM16 WAV, 속도 1.0, 음높이/억양은 해당 엔진 기본값을 명시적으로 기록한다. 기본 Android TTS의 속도 수치를 그대로 복사하지 않는다.
- 캐시 키에 후보·사전 버전·음성·엔진/모델·생성 설정을 포함한다. 입력이 같은 성공 파일은 재사용하고 실패 항목만 재시도할 수 있다.
- 출력은 `*.vfpitch.zip`과 별도 요약 보고서(성공/미일치/다중 후보/실패/용량/버전)다. 팩당 비압축 250MiB 이내로 분할하며 각 팩은 독립적으로 설치 가능하게 한다.
- 대략적인 PCM 크기는 초당 48,000바이트이다. 실제 단어 수·후보 수·길이를 측정해 설치 전 용량을 제시한다. 무료 API 비용과 별개로 PC 저장 공간·생성 시간은 필요하다.

## 9. 가져오기 안전성 및 공간 관리

- manifest/schema, 파일 수(최대 20,000), 비압축 합계(250MiB), 파일별 크기(음성 최대 10MiB), WAV 헤더·시간(최대 60초), 경로, 해시를 검증한다.
- 절대 경로, `..`, 심볼릭 링크, 중복 경로, 실행 파일, manifest 외 파일을 거부한다. 압축 헤더의 크기뿐 아니라 실제 해제 바이트에도 제한을 적용한다.
- 해시는 손상 검출 수단이지 발행자 인증이 아니다. 사용자가 지정한 파일만 가져오며 다운로드 자동 설치는 하지 않는다.
- staging에 스트리밍 해제·검증하고 새 인덱스를 원자적으로 활성화한다. 중단·실패 시 기존 팩과 선택은 유지한다. 앱 재시작 시 미완성 staging만 정리한다.
- 설치 중 여유 공간이 부족하면 시작/진행을 중단하고 필요한 용량을 안내한다. 기존 단어 데이터나 다른 팩을 자동 삭제하지 않는다.
- 가져온 음성은 캐시 디렉터리가 아닌 앱 전용 파일 영역에 둔다. ‘음성팩 관리’에서 용량/출처/사용 중 여부를 보여주고 사용자가 삭제한다.
- 팩 삭제 시 선택은 보존하고 음성만 ‘팩 필요’ 상태로 바뀐다. 공유 음성 파일은 다른 설치 팩의 참조가 없을 때만 삭제한다.
- 앱 데이터 삭제/제거 시 로컬 팩·선택이 사라질 수 있음을 안내하고 선택 내보내기를 제공한다. 이 기능에 자동 클라우드 복구가 있다고 안내하지 않는다.

## 10. 재생 통합과 장애 처리

- `StudySpeechRequest`에 의미 및 선택적인 카드 참조를 더한다. 모든 수동/자동 일본어 단어 재생이 하나의 resolver와 playback coordinator를 거친다.
- Android는 기존 MethodChannel에 로컬 WAV 재생/정지 경로를 추가하고 native MediaPlayer를 사용한다. 앱 내부의 검증된 파일 참조만 허용한다. 새 범용 오디오 패키지는 1차 버전에 넣지 않는다.
- 새 요청마다 이전 WAV와 기본 TTS를 모두 정지한다. 카드 이동·되돌리기·화면 이탈·백그라운드 전환에서도 취소한다. 비동기 요청 번호를 확인하여 늦게 준비된 이전 카드 소리가 재생되지 않게 한다.
- 헤드셋 분리, 오디오 포커스 상실, 통화 등에서는 정지하고 자동 재개하지 않는다. 완료/실패 시 리소스를 해제한다.
- 우선순위: 유효한 선택/단일 후보에 대응하는 검증된 팩 파일 → 기존 TTS. 한국어·영어와 지원 외 입력은 기존 경로를 유지한다.
- 파일 오류·재생 실패 시 해당 요청에서 한 번만 기본 TTS로 대체하고 비차단 상태 안내를 표시한다. 반복 오류 알림으로 학습을 막지 않는다.
- 기본 TTS도 실패하면 ‘음성을 재생할 수 없음’만 보여주고 학습은 계속한다. 완료 콜백을 기다리느라 카드 전환을 막지 않는다.
- 사용자 선택으로 기본 TTS만 사용하거나 음성팩 기능을 끄는 즉시 기존 동작으로 돌아갈 수 있다.

Word 모델과 Firestore 카드 저장 코드는 변경 대상이 아니다. 설정값도 기존 프로필 백업에 자동 유입되지 않는 별도 이름공간에 둔다. 파일 SHA-256은 구현 시 SDK 호환되는 직접 의존성으로 고정하고 transitive 의존성에 기대지 않는다.

## 12. 검증 및 완료 기준

### A. 음성 가능성 관문 — 본 구현보다 먼저

- 30개 표본: 酒/鮭, 雨/飴, 橋/箸 6개 + 검증 가능한 추가 24개. 0형/1형/중간/끝 하강, 1박, 촉음·장음·요음·ん, 가나 단어, 복수 후보를 포함한다.
- 각 표본의 원문 사전 항목, 모라 분해, 하강 값, 생성 query, WAV, 듣기 판정을 기록한다.
- API 성공이나 숫자 일치만으로 통과시키지 않는다. 일본어 액센트를 판별할 수 있는 청취 검토를 확보한다. 확보 전에는 ‘청취 미검증’으로 두고 정확 발음 기능의 정식 완료를 주장하지 않는다.
- 무성화 등으로 단순 주파수 추적이 불가능한 박은 임의 보정하지 않는다. 0/끝 하강은 도식과 적합한 연결 발음 표본으로 구별하며 모든 단독 WAV에서 차이가 들려야 한다는 잘못된 기준을 두지 않는다.
- 핵심 최소쌍에서 잘못된 하강이 나타나면 대량 생성을 중단하고 엔진 경로를 수정·재검증한다. 실패를 숨긴 채 다른 공급자를 자동 도입하지 않는다.

### B. 자동 테스트

- 모라 분할·정규화·0..N 범위 및 부적합 문자열 거부.
- 같은 읽기의 다른 표기/뜻 분리, 복수 후보 미확정, 가나/읽기 없음 처리.
- 그래프 데이터와 음성 후보 ID 일치, 오래된 fingerprint/사전 버전 재확인.
- 선택 적용/초기화/재시작 보존/계정 격리/두 폰 파일 병합 충돌.
- 손상 ZIP, 경로 탈출, 중복 파일, 압축 폭탄, 공간 부족, 중단 복구, 중복 설치, 공유 파일 삭제.
- 앞면 비노출, 정답 뒤 노출, 설정 끔, 큰 글자/다크 모드/스크린리더, 긴 단어.
- 연속 탭·후보 변경·카드 스와이프·되돌리기·화면 이탈 시 이전 음성 미재생.
- feature 테스트에서 Firestore 카드 write/delete 호출 0회, 카드 원문 snapshot 동일, 기존 전체 Flutter 테스트 통과.

### C. 실기기 수용 기준

- A52s와 다른 연결 휴대폰에 같은 팩/선택 파일을 설치했을 때 같은 카드에서 같은 후보·파일을 사용한다.
- 비행기 모드에서 가져온 음성 재생, 기본 TTS 대체 상태, 앱 재시작 후 선택 유지가 동작한다.
- 통화/헤드셋 분리/백그라운드/빠른 카드 전환 때 음성 겹침 및 잔여 재생이 없다.
- 회독·이어서하기·즐겨찾기·되돌리기·가나 상세·한자 브라우저 뒤로가기 회귀가 없다.
- 기기 미연결 시 자동 검증/에뮬레이터 결과와 실기기 미확인을 구분한다. 연결할 때까지 실기기 완료로 보고하지 않는다.

## 13. 구현 순서와 중단 기준

1. 30개 표본 생성 도구와 출처 묶음 → 엔진 액센트 제어 및 청취 검증. 실패하면 여기서 멈춘다.
2. 순수 모델·모라·사전 매칭·독립 저장소와 단위 테스트.
3. PC 대량 생성/재개, 팩 검증/가져오기/선택 파일 이전.
4. 기존 음성 경로에 WAV 우선 재생·취소·TTS 대체 통합.
5. 정답 뒤 높낮이, 후보 선택, 설정/팩 관리 화면.
6. 전체 회귀 테스트 및 실기기 검증. 계정·카드 데이터 무변경 확인.
7. 결과와 미확인 항목 보고. 배포 요청이 있을 때만 버전/릴리즈 작업. 개인 팩은 공개 릴리즈에서 제외.

모델 크기·생성 시간·정확도 수치는 표본을 측정하기 전 확정하지 않는다. 본 사양은 확정하되, 합성 품질은 검증 관문을 통과해야 한다. 이는 미정 설계가 아니라 구현 중 확인해야 하는 수용 조건이다.

## 14. 비용·출처·한계

- 이 설계에는 유료 API 호출과 상시 서버 유지비가 없다. 단, PC 자원·파일 전달·저장 공간 비용이 있을 수 있으며 ‘모든 비용 0원’을 보장하지 않는다.
- 사전 snapshot과 가공 액센트 데이터를 분리하고 원본 버전·변경 내역·저작자·라이선스를 팩과 앱에서 확인 가능하게 한다. Kanjium의 CC BY-SA 및 상류 데이터 고지를 보존한다.
- Nemo 음성은 공식 약관에 맞는 크레딧을 앱과 팩에 포함한다. 배포 시점에 선택 음성의 추가 조건과 공식 표기 양식을 다시 확인한다. 데이터 라이선스가 앱 전체에 자동 적용된다고 단정하지 않는다.
- 억양은 문장·문맥·방언·발화에 따라 달라진다. 사전 액센트 도식은 실제 F0 곡선이 아니며 합성 음성도 원어민 녹음의 정확성을 보장하지 않는다.
- 이후 확장 후보: 선택값만 별도 클라우드 동기화, 검증된 의미 사전 연계, 개인 서버 생성, 연결 발음 비교. 이번 버전에 암묵적으로 포함하지 않는다.
